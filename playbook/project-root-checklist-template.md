# 项目根 1 层防错清单（模板）

- 定位：放在每个项目根目录的 `1层-防错清单.md`，**只收本项目专属教训**；通用教训一律回全局清单（判层口诀见下）。
- 在全局体系中的位置：建队后开工先读的第一份文件（顺序：项目根 1 层清单 → 全局速查清单 → 合同点名的深查卡）。
- 维护接口：审核漏检的新错误按回流流程先立案，判"专属"后落进本清单（沿用本项目编号制式）；判"通用"则回全局清单。

---

## 判层口诀（先判层，再动笔）

**去掉项目专名，规则还成立 → 通用（回全局清单）；不成立 → 专属（进本清单）。**

- 例：「P1 关键字段必须勾稽」——去掉 P1 后"关键字段必须勾稽"仍成立？成立则这条其实该进全局清单；不成立（仅因 P1 的字段口径特殊才需要）才进本清单。
- 两可时判通用（防线更厚），台账备注「判层存疑待终审」。

## 模板正文（复制这一块到项目根去填）

```markdown
# 1层-防错清单（<项目代号> 项目专属）

- 版本：v1（<日期>）
- 维护规则：编号只增不改、永不重排；作废条目标"已停用"不删号；每次变更更新文尾对账表并同步总索引。
- 适用范围：仅本项目；通用教训已回全局清单（全局清单版本：<x.y，日期>）。
- 开工先读顺序：本清单 → ~/.dsh/防错体系/审核员速查清单.md → 任务合同点名的深查卡。

## 条目（▪ 实点 = <N> 条）

▪ 1｜<编号制式：项目前缀-序号，如 T3-1 / SB-1 / L2-1>
   - 触发场景：<什么时候轮到这条，一句话>
   - 规则句：<本项目专属的必须动作/禁令；带本项目特有口径或路径>
   - 来源：<台账键 B码:会话短id:E## 或复盘日期>｜severity：<blocker/high/medium/low>

▪ 2｜…

## 对账（G1）

| 项 | 数 |
|---|---|
| 条目实点（逐条 ▪ 数出） | <N> |
| wc -l 行数 | <M>（行数 > 实点属正常：头注+空行） |
| 其中 blocker/high | <n1>/<n2> |
| 本轮回流新增 | <k> 条（键：<...>） |
```

## 填写示例（三条脱敏示例条目）

```markdown
▪ 1｜T3-1
   - 触发场景：任何要报"合计、总数"的出口前
   - 规则句：本项目台账键必须先按"分项和=总数"复算一遍再写进任何交付物；
     台账唯一键用三段式 批次码:会话短id:E##，禁止单用 E##
   - 来源：B62:3f47a3cb:E04｜severity：high

▪ 2｜T3-2
   - 触发场景：改本项目的口径/基线数字之后
   - 规则句：必须 grep 旧值全项目传播检查并逐处回改，再在交付说明中写明新旧口径
   - 来源：B62:2ee804:E01｜severity：medium

▪ 3｜T3-3
   - 触发场景：动本项目源文件与交付压缩包前
   - 规则句：先写临时文件→校验→一步原子替换，禁止就地改写；改前 tar 备份一份
   - 来源：B62:3f47a3cb:E04（就地改写截断事故）｜severity：high
```

## 与其他层的关系

| 层 | 文件 | 收什么 |
|---|---|---|
| 全局纪律 | `~/.dsh/防错体系/审核员速查清单.md` | 跨项目通用纪律（G/R/T + RL + 48 张机制卡） |
| 全局机制 | `~/.dsh/防错体系/` 其余正本 | 运维纪律、协作经验、合同模板 |
| **项目专属** | **本项目根 `1层-防错清单.md`** | **仅本项目教训（判层口诀判"专属"者）** |
| 任务合同 | 每份任务方案 | 【清单声明】选中条目 = 必查项最低要求 |

## 常见错误（发出前自查）

1. 把通用教训收进项目清单（判层口诀没走）→ 回流改判，回全局清单。
2. 项目根明明有本清单，任务合同却写"本项目无" → 方案作废打回。
3. 编号中途重排 → 违反"编号只增不改"；作废标"已停用"不删号。
4. 只加条目不更新文尾对账表 → 数字对不平，下轮回流会被拒。
