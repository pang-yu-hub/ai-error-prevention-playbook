# 团队合同模板（六栏 · 全局版）

- 用途：队长建团队、派任务时，把"模板正文"整块复制进每份任务方案，六个栏目一个不落全部填好。
- 配套文件：`~/.dsh/防错体系/审核员速查清单.md`（纪律条目 G/R/T 编号引用；深查底座 = 该清单 §四 通用机制卡 U-x 号）。
- 一句话规矩：**方案缺【清单声明】栏，整个方案作废、直接打回。**

---

## 设计动机（为什么有这几栏）

- 【工作区】栏的由来：实测一份审核合同写了"抽 12 行反查四格、以某版本原文件为准"——却从头到尾没写这些文件在哪个目录。审核员开局只有通用规则、没有任何项目路径，直接卡住。结论：**合同里最基本的信息不是"查什么"，而是"去哪查"**。所以【工作区】设为第一栏；审核员侧对应 R6（先核工作区）。
- 【清单声明】只写必查项，审核员按 R7 自行增补适用条目——**双层选择，防队长挑漏**。

## 使用说明（队长必读）

1. **什么时候用**：建团队、派任务、写任务方案的时候。每份执行任务方案、每份审核任务方案，都要带这套栏目。
2. **怎么用**：把下方"模板正文"整块复制进方案，照着括号里的提示逐项填。六个栏目都是必填；"没有"也是一种填法，但不许空着。
3. **打回规则（硬性，审核与 owner 收货时都照此执行）**：
   - 缺【工作区】栏或缺【清单声明】栏 → 整个方案作废，直接打回；
   - 【清单声明】里没写"适用清单版本"，或没写"选中条目编号" → 同样作废打回；
   - 缺【验货】栏或缺【破坏性动作】栏 → 打回；没有破坏性动作就写"无"，不许空着；
   - 项目根目录明明有"1层-防错清单.md"，方案却写"本项目无" → 打回。
4. **owner 批准时核什么**：只核【清单声明】栏——填了没、版本对不对、编号对不对。十秒钟。这就是整个体系的人审关卡。
5. **条目编号从哪来**：全部引自《审核员速查清单》（全局版）——G 系列（操作员条目）给干活的人写进执行合同；R 系列（审核员条目）给审核的人写进审核合同；T 系列（队长条目）不用写进方案，是队长自己的纪律。项目专属条目引自项目根目录的 1层-防错清单.md。深度机制/案例查询用速查清单 §四 通用机制卡 U 卡号（【清单声明】可选「深查卡编号」行填写）。
6. **建队流程对照**：读两份全局文件 → 按任务类型挑条目 → 照本模板填六栏 → 方案交 owner 批准（核【工作区】栏+【清单声明】栏）→ 执行与审核 → 收尾核卡与范围审计。

## 模板正文（复制这一块去填）

```
【工作区】（必填第一栏。缺此栏，审核员/成员无处下手，方案作废）
- 项目根：____（本任务所有文件的所在目录，绝对路径）
- 防犯错相关文件目录：~/.dsh/防错体系
- 关键文件：____（逐个列：名称=绝对路径，如 V1.7原文件=…、底稿=…、证据=…）
- 开工先读：①项目根/1层-防错清单.md（若存在）②~/.dsh/防错体系/审核员速查清单.md
  ③队长点名U卡时必读 ~/.dsh/防错体系/审核员速查清单.md §四 对应 U 卡

【任务内容】（必填第二栏）
- 要干什么：____（例：更新交付 Excel 的 Q3 数据页，改 3 处数字）
- 产出：____（改完后的文件绝对路径）
- 给谁：____

【清单声明】（必填栏。缺此栏，整个方案作废）
- 性质：这里是队长选定的【必查项·最低要求】，不是全部——审核员开工读完速查清单全文后，
  可自行增补适用条目（R7），增补条目在审核记录中标注"审核员增补"
- 适用清单版本：（例：审核员速查清单 全局版 v1，2026-10-20）
- 选中条目编号：（例：操作员 G1、G2、G6；审核员 R1、R5）
- 深查卡编号：（可选，无则写「无」；例：U-A2、U-D1——编号见速查清单 §四 U 卡号）

【验货】（交付前验证 + 卡路径）
- 交付前验证：（逐条写：验证什么、用什么工具或命令验、出示什么证据）
- 卡路径：（本次验证必须覆盖的具体文件和目录路径，逐条列出；路径之外的产出视为没验）

【破坏性动作】（没有就写"无"，不许空着）
- 动什么：（删除了什么、覆盖了什么、往项目外发了什么）
- 数据去向：（动过的数据去了哪里，被覆盖的原件有没有备份、备份在哪）
- 回滚方式：（出了问题怎么一步步恢复原状）

【项目专属清单】（项目根目录下有"1层-防错清单.md"就在这里点名；确认没有就写"本项目无"）
- 清单路径：（例：项目根/1层-防错清单.md）
- 引用条目编号：（本项目清单里的条目号，逐条列出）
```

## 填写示例（一个小任务的完整填法，已脱敏）

```
【工作区】（必填第一栏。缺此栏，审核员/成员无处下手，方案作废）
- 项目根：<project-root>（本任务所有文件的所在目录，绝对路径）
- 关键文件：<project-root>/底稿/源表.xlsx；<project-root>/证据/上一版交付.xlsx
- 开工先读：①<project-root>/1层-防错清单.md（若存在）②~/.dsh/防错体系/审核员速查清单.md
  ③队长点名U卡时必读 ~/.dsh/防错体系/审核员速查清单.md §四 对应 U 卡

【任务内容】（必填第二栏）
- 要干什么：更新交付 Excel 的 Q3 数据页，修正 3 处数字
- 产出：改后的 Excel（绝对路径：<project-root>/交付/示例成果.xlsx）
- 给谁：owner

【清单声明】（必填栏。缺此栏，整个方案作废）
- 性质：这里是队长选定的【必查项·最低要求】，不是全部——审核员开工读完速查清单全文后，
  可自行增补适用条目（R7），增补条目在审核记录中标注"审核员增补"
- 适用清单版本：审核员速查清单 全局版 v1，2026-10-20
- 选中条目编号：操作员 G1、G2、G6；审核员 R1、R5
- 深查卡编号：无（示例；深查时填 U 卡号，见速查清单 §四）

【验货】（交付前验证 + 卡路径）
- 交付前验证：①用表格软件真实打开交付文件一遍，确认能打开、内容齐全、无报错，把打开结果
  作为证据（G2）；②分项求和与总数逐表核对，把两边数值写进交付说明（G1、G6）
- 卡路径：交付文件 <project-root>/交付/示例成果.xlsx（只此一个文件；路径之外的任何产出
  不属于本任务）

【破坏性动作】（没有就写"无"，不许空着）
- 无

【项目专属清单】（项目根目录下有"1层-防错清单.md"就在这里点名；确认没有就写"本项目无"）
- 清单路径：本项目无
- 引用条目：编号加相关具体内容，是审核清单，需要审核员以及人都能看懂（G14：禁止黑话）
```

## 常见打回原因（发出前对照自查一遍）

| 打回原因 | 对应栏目 |
|---|---|
| 忘了复制【清单声明】整栏 | 【清单声明】 |
| 清单版本号没写、写错，或引用了不存在的版本 | 【清单声明】 |
| 条目编号瞎写（速查清单里——含 §四 U 卡——都没有这个号） | 【清单声明】 |
| 不适用条目不写原因，只写"略" | 【清单声明】 |
| 【验货】只写"检查一下"，没有工具、路径、证据 | 【验货】 |
| 【破坏性动作】空着，没写"无" | 【破坏性动作】 |
| 项目里明明有 1层-防错清单.md 却写"本项目无" | 【项目专属清单】 |
