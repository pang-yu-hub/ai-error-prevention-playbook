# 教训卡模板（错误台账 + 回流立案）

- 用途：每团队/项目一份错误台账（如 `errors-ledger.md`，或记忆系统的专用主题文件），**追加写**。每条事故一张教训卡。
- 配套：回流判层口诀见 `docs/methodology.md` §3；纪律条目编号见 `playbook/reviewer-quick-reference.md`。
- 核心纪律：**台账条目到"三选一规则化"的转化率必须 100%**——禁止只写进记忆完事。

---

## 1. 台账立案字段（回流第①步）

每条事故先在台账追加一行（追加写，不改旧行）：

| 字段 | 说明 |
|---|---|
| 键 | 唯一键 = 三段式 `批次码:会话短id:E##`（如 `B4:a60aea7e:E07`）；合桶唯一键 = 后两段 `会话短id:E##`（裸 E## 跨会话重复，禁止单用） |
| 日期 | 发现/立案日期 |
| 项目 | 项目代号（P 码）或"通用" |
| 一句话症状 | 可观察的错误行为 |
| severity | blocker / high / medium / low |
| 分类候选 | 主类（A–I/Z）＋ 第二候选 |
| 证据指向 | 会话短id ＋ 文件/行号等可回溯定位 |

## 2. 教训卡模板（复制这一块去填）

```markdown
### 教训卡 <编号>：<一句话标题>
- 日期 / 来源任务：
- 现象（可观察的错误行为）：
- 根因（为什么发生；未查根因不得动手修）：
- 修复（本次怎么解决的）：
- 规则化（三选一，至少填一项；禁止留空）：
  - [ ] 可测量规则 → 进 L1 注入层：触发条件＋必须动作/禁令＋度量标准（注明注入层与位置）
  - [ ] 流程步骤/脚本 → 进 L2 流程层：进哪个流程/skill 第几步，或捆绑什么脚本
  - [ ] hook/门禁 → 进 L3 强制层：拦截事件＋检查命令＋失败行为（显式 fail-closed）
- 检查命令（供交付前 GATE 引用）：
- verified: <日期> ｜ 下次复核：<日期>
- 复发计数：<n>（≥2 → 强制升级为 hook/门禁）
```

## 3. 填写示例（已脱敏）

```markdown
### 教训卡 L-007：交付 Excel 未真实打开即报完成
- 日期 / 来源任务：2026-11-10 / 数据更新任务（P1 项目）
- 现象：宣布"交付完成"后 owner 打开文件发现页签空白、公式报错
- 根因：生成脚本退出码为 0 被当成"内容正确"；无打开验证步骤
- 修复：补打开验证；把 G2 写进任务合同【验货】栏
- 规则化（三选一）：
  - [x] 可测量规则 → L1：任何交付文件报告完成前必须真实打开一次并出示证据（注入位置：全局记忆红线集）
  - [x] 流程步骤/脚本 → L2：交付前 GATE 第 G2 步（打开→记录页数/可见内容/报错）
  - [ ] hook/门禁 → L3：（暂无；复发 ≥2 时升级）
- 检查命令：打开工具载入交付文件，记录可见内容摘要与报错数
- verified: 2026-11-10 ｜ 下次复核：2026-11-24
- 复发计数：1
```

## 4. 治理纪律

1. **双周审计**：去重、删过期、查冲突；>3 个月未验证的条目删除。
2. **复发升级**：同卡复发 ≥2 次说明 L1 注入不够，**强制升级为 L3 硬门禁**（soft → hard）。
3. **转化率 100%**：台账条目"三选一"填充率必须 100%，回流时逐条检查。
4. **回流接口**：本台账是回流循环的入口——新教训先进台账立案（三段键），再按判层口诀分通用/专属路径蒸馏（见 `docs/methodology.md` §3.2 回流七步；跳过立案直接改清单 = 违规回流）。
5. **证据形态**："模型说它检查过了"不是证据；只有新鲜运行、可复跑的命令输出才是证据。

## 5. 声称-证据对照表（防"打折验证"，供 GATE 引用）

| 声称 | 算数的证据 | 不算数 |
|---|---|---|
| 测试通过 | 本次输出：0 failures | 上次的结果、"应该过了" |
| 构建成功 | exit 0 | linter 过了、日志"看起来正常" |
| bug 修好 | 原始症状复现测试通过（撤销修复必须变红） | 改了代码就假定修好 |
| 子代理完成了 | 版本控制 diff 实证变更 | 子代理自报"成功" |
| 需求满足 | 逐条 checklist 对照 | "测试过了=完成" |
| 模型自查过了 | —— | 无外部证据锚点的自查 |

**红旗词**：should / probably / seems to；验证前表达满意；任何"换个说法所以不适用"都是借口——精神高于字面。
